# 项目约定

## 使用工具箱

不熟悉命令时先查 help，了解后直接调用。查询、准备、修改和提交均使用 Govel 的公开 MCP／CLI 入口；`get_tool_help` 可按意图、操作 ID、MCP 名或 CLI 命令查参数，并返回本机 CLI 路径。CLI 使用 `novelctl.py --help` 或具体命令的 `--help`；无需每一步重复读帮助。

“续写这个／接着写／继续上次”先调用 `prepare_task`，参数为本项目绝对路径 `projectRoot`、`task=continue`、`view=model`。进度查询用 `project.overview`，读正文用 `project.prose`，读计划用 `source.chapter-plan`；其他任务先按 help 选择入口。工具返回缺项、冲突或无已授权任务时，沿其恢复查询处理，不自行解析内部 JSON、遍历项目文件来判断流程，也不编写临时脚本代替领域操作。

准备后的材料使用工具返回的读取动作、凭据与分页引用；修改使用预览、明确批准和提交。MCP 不可用时可调用同一工具箱 CLI。本文、工具箱根 Skill 和宿主工具说明用于初始指引；用户原始输入可交给导入入口。开发或故障排查另按作者明确要求处理。

## 资料与批准

本项目的设定与规划唯一真源是 `.govel/structure.json`。稿件正文保存在登记章节的 `filePath`，审批、事务和版本证据保存在 `.govel/` 的相应运行记录中。

- 创意讨论在当前 App 内进行。只有已经确定、且当前任务授权落实的内容才提交项目工具；未决选项继续讨论。
- 先查询源 schema，再按对象、属性、时间和内容身份查询。长片段按返回定位续读，分页游标不能跨源版本复用。
- 写入片段时同时声明所属、内容绑定、时间效力和实际依赖。所属和依赖不能替代内容绑定。App 对绑定的语义正确性负责，工具校验结构、引用和版本。
- 修改使用批量预览与结构提交。提交后的影响按范围继续读取；App 检查语义、登记回执，不能把机械关联直接当作正文冲突。
- 正文由 App 创作和修改。设定工具不顺带改正文；正式发布继续遵守当前工位契约、审批和事务条件。
- 阶段 A 及状态候选使用源计划摘要 `sourcePlanHash`。查询章节计划取得实际输入，不使用导出 Markdown 的文件 hash 代替源审批。
- 阅读 Markdown 只在作者需要时导出；无需维护，删除或编辑导出不会更新真源。若作者要落实导出中的修改，应比较对应版本后生成明确源变更。
- 正文证据以章节 ID、稿件 hash、字符范围和引文定位；文件变化后重新定位。未登记的隐含依赖仍需 App 判断，零命中不能解释为全书无影响。

查询、检查与导出的成功不等于已经完成语义审查或正式发布。应以各自绑定当前输入的回执说明实际完成了哪一步。

本工具箱只支持当前项目格式。旧项目按外部小说人工整理后迁入；不得通过旧审批、旧回执或兼容层恢复当前写入权。入口选择与建章／审校／提交流程按工具箱根 Skill 执行：先取当前审校表单，再填写实际判断和证据；工具处理文件、hash 与重试。MCP与CLI共享领域校验，直接修改机器真源不能替代预览和批准。

审校与精简返回按根 Skill 的模型交付方式执行。正式正文由定稿事务创建并建立归属，未知目标冲突不能用删除或覆盖消除。

外部原稿导入后，AI 按根 Skill 沿 `import.verify`、`import.organization-status`、`import.organization-prepare/read/preview` 分批提炼和审阅，不把任务推回作者手工补资料。回溯梗概和事实统一登记在结构真源，规划目录可以为空；采用原稿是当前批准的回溯审阅，不补造历史 A/B，也不自动授权新章。动作提供的 JSON arguments 可通过 help 生成 CLI 旗标，不靠拼写猜测。
