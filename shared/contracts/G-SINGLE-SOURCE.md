# 单一设定与规划真源

本契约适用于 manifest 声明的唯一当前项目格式。设定与规划使用单一结构真源，正文使用当前归属绑定。旧项目按外部小说逐本人工整理迁入，不提供旧格式读取、双轨运行或版本专用升级链。

## 讨论与落地

- 未确定的创作方向留在 App 对话中讨论。只把作者已经确定、且当前授权涵盖的内容交给源变更工具。
- App 先用 `source schema`、`source query`、`source chapter-plan` 等有界入口取得稳定 ID 和必要上下文，再构造 `source change-preview`；不得凭显示名或会话记忆猜 ID。
- 预览验证通过且仍在既有授权范围内时可连续提交。新增剧情取舍、对象歧义或连带正文修改交还作者决定。

## 真源与呈现

- `.gnovel/structure.json` 是设定、卷／单元／弧／章计划、时间、呈现和绑定的唯一作者真源。`.gnovel/` 下的问题、证据、审批与事务回执是运行证据，不覆盖作者事实。
- `source query`、`source render` 和 `source export` 使用同一个选择器。导出 Markdown 只按需生成，不维护、不反向导入，也不参与任务就绪。
- 片段按稳定 ID 管理。内容关联决定筛选去留；所属、依赖、来源、时间不充当内容关联。任一入选且未排除的内容关联存活时保留整段；全部失去时隐藏。混合段保留原文，不做逐词脱敏。
- 已提交使用过的身份不得在删除后分配给新内容；历史身份沿既有事务记录核验，不另建身份账本。正常修改保留当前身份，合法撤销按原撤销证据恢复，未提交预览不占用身份。
- 正文按章 ID 管理；具体证据使用稿件 hash、Unicode 字符范围和引文。不得要求全书每个正文段落永久编号。

## 修改与影响

- App 的一次确定修改以同一批次写入属性、值段、片段和绑定。悬空引用、空内容关联、重复权威、确定时间矛盾及过期基准必须拒绝，不能产生部分写入。
- [M] 混合受审批量只合并同一源快照上的受审提案；每个目标记录仅属于一项，保留旧值、证据、声明批准与原可写边界。预览和提交都重验每项及完整合并结果，不能夹带其他记录或结构归属；任一失败拒绝整批，历史回执不授予当前批准。
- 已使用字段的名称与说明用字段更正项；语义键、类型或适用对象用字段迁移项，并列全其属性与每个已知值及原证据。允许修改项由源模型注册表声明。仅类型变更可转换值；未知态、身份、归属、顺序和效力区间保持，末态仍须符合完整源约束。不得隐式删造值、搬用属性或删除字段。字段及全部声明属性共同占用原批次预算，含未改属性；提交重验完整范围与旧新绑定。变更沿登记依赖使相关审查待复核，不改正文或继承旧批准。
- [M] 同一记录的多处文字补丁按同一份旧文定位；允许同字段的不重叠区间，拒绝重复锚点、区间重叠与父子字段覆盖。规划片段可与事实提案同批提交，但各自复用原校验，规划不得升格为事实或充当事实证据。
- [M] 规划局部补丁绑定旧记录，保留身份与归属；批量补丁仍复用原规划变更门，不能修改事实或把规划升格为事实。同快照的解析引用可交接版本与旧记录绑定，但只涵盖其中已解析的规划目标，不授予批准；未知、错类或过期目标不得补绑。
- 按方案批量修订需保留方案来源指纹、条目引文、目标身份与提交回执的映射；逐项核对当前复核证据。同编号不等于同一要求，提交成功不等于语义完成。复用运行回执，不建立第二份设定或批准真源。
- [M] 方案分段保留原文与版本定位，清单只装配显式选定的范围和目标；临时目标仅由同方案、同条目的未撤销回执唯一解析，缺失或歧义保持未解决。[S] 要求枚举、分段拆合及目标映射由工位判断，材料交付不等于完成审查。
- 已绑定方案与清单的预览在提交边界复核输入，变化后重新核对；回执保留条目与实际改动身份。稳定请求身份不得换载荷复用，已提交或撤销的历史请求不得自动重做。恢复状态从既有计划与回执重建，不另建任务状态真源。
- [M] 仅超时的稳定请求可续期原计划；必须重验源、证据、维护输入、派生器与写集，保留原拟写字节和操作 ID。续期返回新 planHash，提交须绑定该 hash 与明确批准；任一输入变化时拒绝续期。状态查询本身只读。
- [M] 预览冻结逐处修改前后、对象名称、身份和位置，并给出提交入口。长 diff 分页交付；历史无 diff 时不反推补造。
- 设定提交返回登记依赖闭包、章节、正文定位、规则检查和覆盖声明。没有登记关系或未扫描正文时，明确说明缺口；不得声称全书无影响。
- 设定事务不改正文。正文修订由 App 读取影响材料、与作者讨论剧情处理后，通过正文候选和发布流程执行。
- 影响问题按当前动作、当前章范围、适用规则和当前证据判断。后卷延期不阻断当前无依赖章节；当前必过项的延期不等于通过。

## 规则与证据

- 规则分 mechanical／semantic 与 required／advisory 两条轴。机械计数只消费明确登记的事件和规范上限；自然语言命中只能成为候选。
- 语义结论绑定规则版本、登记输入、章节动作和当前证据。相关输入、规则版本或稿件定位变化后恢复待检查；无关修改不整批作废。
- resolved 才表示当前结论已处理；confirmed 和 deferred 保留问题。exception 只有规则明文允许且回执带当前证据时生效。工具验证版本和证据存在，不证明模型判断正确。

## 规划与章节流程

- 配对分类唯一写入同一真源的 `pairs`，不用项目计划散文、标签猜测或另一份分类文本替代。`pairAssessment` 只表达配对库存是否已评估，不重复分类。空集合与缺失评估表示尚未决定；明确没有适用配对须有显式判断和依据。
- 配对使用稳定身份、两个不同的既有人物端点和登记枚举。分类未知、未评估与明确不适用分别记录；非法类型、枚举、悬空端点拒绝写入。配对适用范围由作者声明，省略范围表示全书；卷／弧线／章范围只影响被选中的章节。
- 条件装载逐项报告匹配依据、未命中依据或未解决输入。某配对已命中时可以装载对应契约，但其他适用配对仍未知时保留警告，不得把该工位标成资料完整。只在真实消费该条件的工位检查所需资料，不以一律常驻契约掩盖分类缺失。
- 章节计划同时绑定适用配对、库存评估、条件定义与实际装载的条件契约内容。范围内分类、人物端点、评估依据、弧线条件或契约输入变化后，相关旧审校和写作绑定失效；明确局部范围的配对调整不作废无关章节。缺失输入仍能形成待补清单，不构成通过证据。
- 章节计划由本章有效片段、项目／卷／单元／弧线祖先的有效 plan 片段、适用规则和登记依赖构成，以 `sourcePlanHash` 绑定阶段 A、状态推进和发布预检。祖先归属下的 fact、belief、in_world_text 片段只在被登记引用或依赖时纳入，不因项目归属而自动影响全部章节。章→实体引用包含该实体的属性、所属及关联有效片段；直接片段依赖只取其输入闭包。措辞修改仍按实际输入闭包判断失效，不凭“无语义变化”声明转移批准。
- Writer 只消费已批准的当前 `sourcePlanHash`。阅读导出、旧 outline 文件和维护型卡片不提供替代真源。
- [M] 作者决定先验证不含决定自身的作者内容投影，再将当前适用决定纳入章节计划、影响与上下文。纯章状态、定位与归属代次不改变内容证明；实际依赖变化须待复核，不能因内容回退自动复活批准。新 scopeSnapshot 带唯一用途标记 `author-content`，缺标记或未知标记只保留为 unproven 历史；不双算法试算、不补标记，沿 supersedes 与受审批准刷新。
- [M] 当前项目级作品文风影响所有实际消费章节。未批准 draft 不生效；采用、撤回与 supersede 必须反映到实际相关计划和旧审查，不能把过期的必要作者决定过滤后仍报就绪。
- [M] 带当前用途证明的 active 决定遇到相关受审源变更时，在同一原事务追加 `scopeInvalidatedBy`（操作、revision 与失效范围）；原 scopeSnapshot 与 approval 字段保留。该标记只能降低信用，提交独立重推，通用保存不得改写或删除。撤销或恢复原内容仍保留失效，需新 supersedes 与明确批准刷新。撤销链等价核验须有原操作 after 镜像和对应已提交失效证据，完整 source hash 与 CAS 不忽略这些字段。
- 准备、写作、审校和发布分别检查该动作的适用规则。正式入库历史可保留；相关源变化会使当前复核证据过期，不能抹去历史或沿用旧批准。

## 时间与信息身份

- 作者修订版本、故事时间和阅读呈现分别存取。相对、区间、粗粒度和未知时间保持原状态；没有日期时不补日期。
- `timeSpec` 约束发生点，`range` 的 after／before 是严格先后，保留可行窗口及端点开闭，不代表持续期间。实体／章节起止挂载约束开始不晚于结束；活动自身的发生点不自动等同开始或结束，依赖活动结束时引用明确终点。相对等式、先后与起止须共同可满足；确有数值依据才推导时间，`validDuring` 仍为半开效力区间。
- 客观事实、人物信念、世界内文献和作者计划使用不同 contentRole。人物／势力视角只读取明确登记给该视角的信念或文献；未登记信息不得宣称角色已知。
- 人物视角交付使用文本与时效，作者侧来源备注和依赖说明不随可见片段交付。自动章节上下文按本章起点筛选，无法证明时效的限时内容保留未知计数；起点未定时仍可读无时间限制的认识。显式查询省略 `asOf` 表示全时期，传 null 表示时点未定，两者不能混淆。
- 同一事件可有多个 presentation；回忆或再次提及不复制事件事实。

## 外部稿件

- 原稿是阅读证据，不能直接成为当前项目真源、批准或正文归属证明。
- 人工确定章节、设定、规划和纳入范围后，用当前初始化与领域事务落地。新身份与当前证据重新建立，不复用旧项目机器状态。
- 同文、文件名或旧软件的状态字样都不能替代语义裁定。保留原稿及未决材料，明确说明实际纳入范围。
- [M/H] 受管正文的外改预览保留准确可找回的 H1 与受检 H2；缺 H1 如实显示。原 requestId 固定原章、代次、对象和字节，只到期且材料不变时可续期；H3 不沿用 H2 结论。预览成功不表示采用可执行，独立用户在场能力未提供时不返回普通 commit 作为下一步。正文始终是只读 guard，不进入采用恢复写集。

## 正文合订交付

- 合订稿只使用通过当前正文归属核验的字节；章节状态本身不证明盘上稿件仍是已接纳版本。外部改稿、归属未建立或不明时拒绝交付，不借导出接纳新字节。
- 候选批次通过显式的冻结候选阅读入口导出，标明非正式身份与部分交付；不更改正式合订的默认来源，不产生正文归属或文学批准。
- 状态筛选与缺章分别报告。所选章节缺失而仍有可导出内容时，文件和回执均明确标记部分交付及缺章；没有可交付章节时失败，不产生空成品。
- 已有不同内容的导出目标默认保留；覆盖须明确选择并绑定已检查的目标 hash。发布前复核输入与目标，保全被替换的输出；发生冲突时不覆盖并发写入，交付可定位的保全文件。输出不得写入正文或项目真源。
