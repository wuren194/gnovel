# 长篇连续性合同

设定与规划唯一真源在 `.govel/structure.json`，记录身份、内容角色、关系、时间与登记依赖；查询和变更规则见 `G-SINGLE-SOURCE.md`。正文按章 filePath 管理，缓存与阅读导出不取得作者真源地位。

## 写前

- 使用当前任务的 prepare model 报告读取上下文，单一视角必须指定 POV。来源、缺项、预算与过滤证明由工具生成；未交付材料不能宣称已读。
- Writer 消费经阶段 A 批准的当前 `sourcePlanHash`，包括本章定位、节奏段、篇幅、认知边界和遗留。计划缺失或输入漂移时返回缺项，不能靠旧导出或会话记忆替代。
- Planner 逐项核对前一稳定章、已登记事实与实际依赖。伏笔的埋设、推进、回收预期和当前状态应明确登记，未知字段保持未知。

## 写后与事实回流

候选正文中的 observed effects 是待审内容。Editor 核对计划与事实依据，区分已发生事实、人物信念、世界内文献和作者计划。新增事实先明确内容、owner、内容绑定、时间与依赖，再走源提案／批准提交；正文引证绑定章节、稿件版本与精确引文。

`state_candidate` 绑定当前真源投影、sourcePlanHash 与最终正文；它不承担直接改写设定的职责。空 changes 不证明本章没有事实变化。设定回流、复核和引证完成后再更新摘要，收尾报告分别列出实际结果。

## 提交与跨章

- 工件保存、绑定与登记可交给内置提交操作。批准只确认具体工件，正式正文仍经 finalize 的当前归属、代次与审校门写入。
- 当前章只有在审校、正式入库和连续性收尾完成后才可作为下一章的稳定事实源。不能用一份历史摘要覆盖新的正文或设定。
- 跨章事实变化通过已登记依赖报告影响，未登记语义依赖仍须工位阅读判断。过期或待复核不是“正文已错”的结论，也不授权自动重写。
- 恢复先核对当前 workflow、事务与唯一下一步，不能按记忆选择候选或扩大批准范围。

## 伏笔与设定演变

Planner 在计划中列出本章实际使用、推进或兑现的伏笔；Editor 用可定位正文核验。记忆中的一句提及不自动成为兑现证明。窗口、预算与机械分类使用当前注册表和上下文报告，不在本契约复制数值。

回收伏笔时必须同时补入新的故事钩子，新增数量不得少于本章回收数量。已到期或过期的伏笔必须明确推进、解决或调整预期回收点，不能靠省略记录拖延。推进与回收要有具体的物件、动作或对白段落支撑，单句心理提及不算兑现；种子原文可作为带来源的计划备注保留。

设定是可修订的契约。既有事实的改变须明确旧值、新值、理由、时间和受影响范围，经受审源提案落实。不能事后补记录来掩盖正文未经批准发明的关键角色、规则、事件或关系变化。

没有计划或事实依据的新内容进入待澄清项，由 Planner 与作者决定补注册、改计划或修正文。零检索命中、机械 PASS 和文件保存成功都不替代这个判断。

## 长期检查

Doctor 核验结构、工作流、上下文和工具状态；语义复核保留当前输入与实际结论。缓存可以重建，未解决问题、事实与历史证据不能因整理而消失。
