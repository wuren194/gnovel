# 变更记录

不兼容变更条目以 **BREAKING:** 开头。产品版本以 `toolbox.manifest.json` 为准，以下条目记录各次发行；项目格式与契约版本独立维护。

## 未发布 · 2026-11-10

完善外部贡献规则，新增保留贡献者版权和额外重新授权条款的 CLA 草稿（需律师审阅）、PR 模板、安全报告说明、代码所有者和 GitHub 网页维护清单。补充第三方来源、AI 辅助披露、私人资料边界与核心语义要求。

新增 macOS 工程 CI 和发布内容检查。CLA 使用固定提交版本的维护中 Action，签署记录留在同仓库独立分支，按协议内容摘要区分版本；签署结果绑定当前 PR 提交。分支保护和私密漏洞报告仍需维护者在 GitHub 设置中启用。引擎行为、许可证、manifest 版本和已有测试保持不变。

## 0.5.0 · 原稿回溯整理与完整性校验

自动分章增加中文括号、方括号与序数标题；手工边界允许从首章标题开始，前置内容自动保留，不静默丢弃。序数可能是正文列表，预览提示核对。

新增原稿整理准备、分页读稿和受审预览，AI 提供带引文的实体、关系、事实、回溯梗概及实际审阅结论，沿现有源事务批准提交。作者采用后将已写原稿作为可接续历史，保留原正文及归属，不补造阶段 A/B 或未来授权；原稿、依赖记录、引文或已提交证明变化使相关资格失效。已有风格及摘要工具完成后续接续资料。

新增 `import.verify` 与 `import.organization-status`，分别核验原始字节覆盖及实时整理待办；doctor 复用待办并分开显示数据完整性、创作就绪度。旧 healthy／退出码继续表示全部开工条件，不作为导入完整性结论。help 可把 operation + arguments 转为 CLI，参数名误写为 camelCase 时给出真实旗标建议。实体 ID 错误给出生成前缀与自动分配入口。

## 0.4.1 · 命令帮助与创作入口

新增 `project tools help`／`get_tool_help`，从同一公开操作目录生成参数、CLI 示例和分页分组。支持按意图、操作 ID、MCP 名或 CLI 命令路径查帮助，无需先读取小说项目。顶层 `--help`、根 Skill、项目 AGENTS 模板和 MCP 握手均给出首次调用指引。

补齐续写、继续上次、进度、正文、计划、审校意见、改名、撤销前查询和实体创建等口语路由。无匹配时可沿 help 分组找能力；无已授权任务或流程冲突时，续写错误返回项目概览与诊断动作，保持原阻断及批准条件。已了解命令时直接执行，不要求每次重复 help。

## 0.4.0 · 项目操作与双通道对齐

公开 `novelctl project` 操作全部提供 MCP 入口，共用参数校验、效果分类和领域处理器。新建项目、项目搬移、缓存重建、结构批量预览与日志管理不再因通道不同而缺失；默认工具目录仍按意图或工位收窄。

新增空项目新建预览／批准、完整 ZIP 备份／逐文件核验／批准恢复。恢复保持当前格式项目身份和已有证据，在新目录发布，停止原宿主活跃交接并保存原元数据副本。不可读目录、缺少必需文件、并发变化、路径或摘要错误都拒绝生成完整成功结论。

新增已有项目追加 TXT/Markdown 原稿、已有正文拆分／合并、冻结稿读取与章节来源查询。精确的新章正文、归属和来源证据复用原结构事务，全部来源持续受只读保护；新章待规划，原章与原文保留。新身份不走删除式撤销，回执明确保留身份的补偿方式。

外改正文采用增加 macOS 本机确认，单次能力绑定当前项目、冻结计划、正文摘要和对象，并在提交锁内消费。取消、超时、输入变化或普通批准参数均不能替代本机确认；采用后相关审查失效，保留历史连续性和正文。工程测试模拟确认结果，真实窗口人手验收单独记录。

提交重放与历史读取核对真实已提交事务镜像；拒绝残缺回执的假成功。新增跨 CLI/MCP 调用与来源变化、缺失 guard、伪造写集、备份遗漏等回归。项目格式与工作流版本不变。

## 0.3.0 · 原稿完整导入

新增 CLI/MCP 共用的 `import.preview / inspect / read / commit`。默认自动分章，支持按源文件、起始行与标题调整，无须编写专用脚本或手填结构候选。预览冻结全部原稿字节，识别不到章标题时保留整文件，卷首内容与重复标题提示核对；显式支持 UTF-8、UTF-16 和 GB18030。

批准后在新目录原子发布项目、正文、来源证据和导入回执。工具分配稳定身份、建立新正文归属并重建缓存，源变化、计划漂移、目标冲突或副本损坏均拒绝继续。发布后丢失响应可用同计划重试，不覆盖已创建项目。

导入章节保持 `planning_required`，不生成设定事实、A/B 审查或续写批准。阅读稿导出新增该状态的显式筛选，默认导出范围不变。旧结构候选和只读证据 CLI 保留为高级入口；当前项目格式不变。

## 0.2.0 · 机制 4

BREAKING: 本地数据默认根改为仓库 `local/`，知识库直接位于 `local/knowledge/`。同目录可选的 `provider.json` 自动加载；外部数据可用 `GOVEL_DATA_HOME` 或显式配置指定。Provider 清单不再接受 `roundtable` 字段，圆桌固定读取数据根下的 `roundtable.md`。

用户可直接编辑圆桌 Markdown。非空时使用用户版，缺失或空白时使用通用版；错误编码、不可读文件及符号链接报错。摘要由读取时自动计算，受影响的旧准备与回执失效，知识库不因圆桌编辑而要求重启。

Git 和发行包只包含 `local/README.md` 与空的 `local/knowledge/.gitkeep`。其余本地内容继续排除，检查器拒绝带内容的占位文件。工位仍共用一个圆桌真源，任务结果说明本次使用用户版或通用版。

## 0.1.1 · 机制 3

本地 Provider 的配置与资料可放在仓库内专用的 `local/`。Git 忽略整个目录；打包器、工作区发布检查和归档／历史审核拒绝发布其中的资料，包括强制加入 Git 的反例。其他公开源码目录仍不能作为 Provider 数据根。

配置的 `root` 支持相对于配置文件的普通路径，新建样例使用该形式。整体搬移后资料身份与摘要保持一致；资源摘要、链接和越界检查继续生效。

圆桌默认使用通用版；Provider 声明 `roundtable` 后改为加载唯一私有版本，默认圆桌不进入读取计划。审查计划与读取回执绑定选中的资源摘要和包身份；已声明资料失效时报错，不静默回退。文学职责替换不改变引擎的阶段组席、证据与批准校验。

## 1.0.0 · 机制 1

项目自有代码、规则、文档及原创示例采用标准 AGPL-3.0-only。根许可证随源码分发，第三方许可与署名单独保留。

通用引擎以 Govel 发布。参考资料、题材注册表和专用材料通过仓库外的本地 Provider 装载。包身份和资源摘要进入任务准备与诊断依赖；显式配置失效时拒绝继续使用旧结果。

公开默认配置不带参考数据集，提供一个都市生活示例。此发行版提供 CLI、MCP 和本地 JSON 接口。

公开场景、表达与故事架构契约使用通用判断依据和原创示例。移除强制依赖外部文库的流程与历史资料链接，保留当前计划、事实交接、逐席审校、组织过满反误判和正式采用边界。

叙述安排契约依据本项目的因果完整、修订范围和作者选择要求重新编写；公开稿不保留外部检查体系的改写文本。第三方表面文本指标的窄范围来源及许可另见 THIRD_PARTY_NOTICES.md。
